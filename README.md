# 运转计划助手使用说明

运转计划助手用于规划想乘坐的线路，也可以按实际情况记录已经完成的行程。规划、记录和线路数据都保存在浏览器或导出的 JSON 文件中。

## 1. 从首页开始

1. 通过 HTTP 打开网站首页。不要直接双击 HTML 文件；规划模式需要加载浏览器版 Python 内核和线路数据。
2. 选择「规划」创建计划，或选择「记录」记录已经完成的行程。
3. 进入模式后选择「新建」「最近」或「导入」：
   - 「新建」创建空白行程。
   - 「最近」继续编辑本机浏览器保存的草稿。
   - 「导入」读取此前导出的规划或记录 JSON。
4. 首页右上角可以打开「站信」「使用说明」和「联系作者」。站信包括管理员发布的全站消息及提交线路数据后的审核通知。

草稿自动保存在当前浏览器和设备中。清理浏览器站点数据、使用无痕窗口或换设备后，草稿不会自动转移；需要转移时请导出 JSON。

## 2. 规划行程

### 设置方案

1. 在顶栏选择城市线路库；选择「纯手动」则不加载线路库。
2. 填写方案名和日期。需要连续进出付费区计费时，勾选「付费区模式」。
3. 草稿会自动保存；可使用「撤销」「重做」恢复编辑操作，也可清空全部行程段。

### 添加行程段

点击「添加行程」，选择以下一种录入方式：

- **数据库线路**：输入线路名称或简称，从候选中选中线路，再选起点、到达站和方向。系统根据线路数据库计算运行时间、经停站和方向；配置有快车时也可以选择车种。
- **手动自选**：填写线路名、交通类型、起终点、运行时长、班次文字、经停站和线路颜色。适用于数据库没有收录的线路或其他交通方式。
- **国铁车次查询**：填写起点、终点和乘车日期，查询车次后点击「预填此车次」。检查预填信息并点击「确认并加入」后，系统才会请求该车次完整时刻表、核对乘降区间并加入行程。查询列表本身不会读取经停站。

国铁完整经停时刻表会随行程写入 JSON，并缓存于浏览器，重复使用同一车次和日期时优先读缓存。加入行程后，可在行程卡片展开「完整经停时刻表」查看站次、到发时刻和停留时间。RailKale: Next 每个接口每分钟最多请求 3 次。导入一个月以上未更新（或没有更新时间）的国铁行程时，系统会询问是否重新查询；选择取消会保留文件中的原数据，查询失败时同样保留原数据。接口不可用或无法准确核对乘降区间时，该车次不会被加入。

每段行程还可填写票价、上车前步行时间和备注。手动时刻表可添加一行或多行车次与发到时刻；勾选「按时刻表乘坐列车」时，运行时间按时刻自动计算。

### 调整和检查行程

- 使用每段卡片上的上移、下移、编辑和删除按钮调整行程。
- 行程链条按顺序连接；系统显示换乘提示、线路系统、经停站、时长、站数、票价、彩色时间轴和付费区统计。
- 数据库内同一系统的换乘会自动识别。跨系统转乘需由线路数据明确指定；相同站名本身不代表可以转乘。
- 「智能规划」可勾选想乘坐的线路和想前往的车站，设置可选起点和换乘步行时间，生成覆盖目标的方案。结果会综合换乘次数、转乘次数和时间排序；选择方案后可应用到当前行程。
- 点击「切换到记录模式」可将当前行程带入记录模式。

### 导出规划

点击顶栏下载图标，选择：

- **JSON**：保存完整方案，供以后导入或切换设备使用。国铁行程包含完整经停时刻表及其更新时间。
- **PDF**：打开浏览器打印窗口，选择「另存为 PDF」。有手动时刻表或国铁行程时，相关运行时长会加粗并加下划线强调。

## 3. 记录实际行程

1. 在首页进入「记录」；选择城市线路库，或使用「纯手动」。线路库可按需加载。
2. 填写记录名、日期；如需按付费区汇总，勾选「付费区模式」。
3. 点击「添加一段行程」，按实际乘车顺序添加记录：
   - 使用数据库线路时，选择线路、快车服务（如有）、起终站及方向，系统计算线路运行时间。
   - 手动录入时，填写交通类型、线路名、方向、站点和运行时长。
   - 可填写起止时间、车次、车型、票价、备注及本段自定义字段（例如座位、编组）。
4. 使用行程卡片上的上移、下移、编辑和删除按钮整理记录；可在侧栏添加整次运转的自定义字段和备注。
5. 查看全程用时、时间轴及统计。点击顶栏下载图标，可导出 JSON 或打印为 PDF；有时刻表或国铁行程时，相关用时会加粗并加下划线。
6. 「切换到规划模式」会把当前记录带入规划模式。规划和记录 JSON 可以互相导入。记录模式导入时不会联网刷新国铁数据；如需刷新，请先在规划模式导入。

## 4. 线路数据工坊

线路数据工坊用于查看、编辑和提交城市线路数据库。

1. 选择城市；可从空白数据或已有城市数据创建新城市，也可上传 JSON 覆盖当前编辑内容。
2. 在左侧选择线路。在线路图中可点选站点、拖动站点排序，或点击区间的「＋」插入站点。
3. 在「线路属性」调整线路名称、简称、类型、颜色、运营方、所属系统、首末班车、发车间隔和方向等信息。
4. 编辑区间运行时间、线路站点与分支；支持配置快车停靠站和跨线交路等线路数据。
5. 在右侧维护城市的线路系统、换乘关系、同站异名关系和站外步行，并查看数据校验结果。
   - 同一系统内的换乘按换乘处理。
   - 跨系统只有明确配置的站点对才会连接，并按转乘处理；同名站不自动连通。
6. 「源码」视图可查看和编辑完整 JSON；应用源码前会校验数据。
7. 使用「导出数据」保存本地 JSON；「还原」放弃未提交修改并恢复已发布数据。
8. 确认校验后点击「提交审核」，填写修改说明（公开）和可选联系方式（仅管理员可见），检查差异预览后提交。通过审核的数据立即对全站生效。

## 5. 数据审核台和站信

### 查看提交和线路数据

数据审核台公开展示提交说明、差异、审核结果、已发布数据及回滚记录。可按「待审核」「已通过」「已驳回」「已回滚」或「全部提交」查看；提交详情可展开差异。联系方式只对管理员显示。

### 管理员操作

1. 点击「管理员登录」，输入站点维护者配置的管理员口令。
2. 在待审核列表检查数据和差异，可通过并生效、驳回或隐藏提交。
3. 在「已发布数据」管理当前覆盖数据；可从「回滚记录」查看历史操作，并回滚到内置数据或可用历史版本。
4. 可按提交者 IP 指纹设置有期限或永久封禁。IP 指纹用于限制重复恶意提交，不用作站信收件人识别。
5. 在「站信管理」发布全站站信，可立即发布或设置未来发布时间；可删除已发布或待发布的全站站信。

新提交通过或驳回后，系统会自动给提交者发送包含审核结果的私密站信。收件凭证保存在提交时使用的浏览器中，因此换设备或清除站点数据后无法恢复；启用此功能前已提交的记录没有收件凭证，不会收到通知。访客可在首页右上角「站信」查看消息。

## 6. 常见问题

- **页面打不开线路数据**：确认通过 HTTP 访问；首次加载需要下载浏览器运行时和线路数据。
- **线路库没有某条线路**：可在规划/记录中手动录入；也可在数据工坊补充线路并提交审核。
- **国铁查询或经停核验失败**：确认车站名称和日期正确，稍后重试；每个 RailKale: Next 接口每分钟最多请求 3 次。读取到已缓存数据时无需再次请求。
- **导出 PDF**：在浏览器打印窗口中选择「另存为 PDF」。若未看到颜色，可在打印设置中启用背景图形。
- **找不到草稿或私信**：草稿、未读状态和私信收件凭证均依赖当前浏览器站点数据；清理数据或换设备后无法自动恢复。定期导出 JSON 备份行程。
- **审核、提交或站信服务不可用**：在线服务需要网站部署了 Netlify Functions 和 Blobs；纯静态 HTTP 服务器仅能运行本地规划和记录功能。

## 7. 本地开发与部署

仅预览静态页面时，可在仓库目录启动 HTTP 服务器：

```bash
python -m http.server 8010
```

完整运行审核、提交和站信接口需要安装依赖并启动 Netlify Dev：

```bash
npm install
npx netlify-cli dev
```

运行检查和生产构建：

```bash
npm test
npm run build
```

部署到 Netlify 时，在站点环境变量中配置管理员专用的 `ADMIN_TOKEN`，然后部署。审核台不应公开管理员口令。
